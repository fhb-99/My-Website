# 用户端真实内容与阅读体验设计

## 目标

用户端不再导入、显示或在接口失败时回退到 `placeholders.ts` 中的示例数据。文章、站点配置、碎碎念和项目均从 C++ 后端公开接口读取；没有内容时展示真实空状态，接口失败时展示错误和重试操作。

本期同时完成文章发现和阅读体验：文章搜索、标签筛选、分页、封面、阅读进度、目录、上一篇/下一篇、复制链接，以及仅保存在当前浏览器的收藏。

## 范围

包含：

- `user-web` 的首页、文章列表、文章详情、碎碎念、项目、公共布局和必要的状态/API 模块。
- C++ 后端的公开读取接口、SQLite 表和查询。
- 文章搜索、标签、分页和相邻文章的公开接口。
- 面向新行为的自动化测试与构建验证。

不包含：

- 管理端对碎碎念、项目和站点配置的 CRUD。
- 用户账号、跨设备同步收藏、订阅或通知。
- 全文搜索引擎重构；本期继续使用 SQLite 参数化 `LIKE` 查询。
- 将旧的静态 HTML 页面迁移或删除。

## 接口与数据

### 站点内容

- `GET /api/config` 返回 `{ title, subtitle, announcement }`。数据存放在现有 `site_settings`，使用独立键名；不返回审核配置或其他管理数据。
- `GET /api/notes?page=&limit=` 返回 `PageResult<NoteItem>`。新表 `notes` 包含内容、心情、是否发布和创建时间；公开查询只返回已发布项，按创建时间倒序。
- `GET /api/projects?page=&limit=` 返回 `PageResult<ProjectItem>`。新表 `projects` 包含名称、摘要、链接、标签、排序、是否发布和创建时间；公开查询按排序和创建时间返回已发布项。

服务首次启动只创建表，不写入演示内容。数据为空时是正常状态，不由前端制造示例数据。站点配置字段为空时，公共布局隐藏对应标题、副标题和公告，不用 `My Blog` 等默认文案替代。

### 文章发现

- 扩展 `GET /api/posts?page=&limit=&q=&tag=`，仍返回 `PageResult<PostSummary>`。
- `q` 在标题、摘要和 Markdown 正文中检索；`tag` 采用精确标签匹配；二者可同时使用。
- 新增 `GET /api/tags`，返回标签名称和已发布文章数量，用于文章页的筛选器。
- 保留现有 `GET /api/search` 以兼容旧调用；用户端改为只使用带查询参数的 `/api/posts`，避免现有数组类型与 `{ data }` 响应不一致。

### 文章阅读

- 新增 `GET /api/posts/{id}/navigation`，返回按发布时间排序的上一篇和下一篇公开文章；不存在的一侧返回 `null`。
- 详情页继续通过现有文章详情接口读取正文，若没有封面、正文标题或相邻文章，对应 UI 不渲染，而不是替换为示例文案。
- 收藏只保存文章 ID 到浏览器 `localStorage`，不请求后端；复制链接优先使用 Clipboard API，失败时给出明确提示。

## 前端交互

### 公共站点状态

新增只读站点配置 store/composable，首次加载后缓存 `title`、`subtitle` 和 `announcement`。公共布局、首页和页脚共用该状态，避免多次请求和各页面出现不一致的标题。现有 `data/placeholders.ts` 将删除，业务页面不再导入它。

请求状态统一为 loading、ready、empty、error：

- loading：显示轻量骨架或“正在加载”。
- empty：显示“暂未发布内容”，不显示任何示例记录。
- error：显示后端错误和“重试”按钮；已成功加载的数据不因一次刷新失败被清空。

### 文章列表

文章页把 `q`、`tag` 与 `page` 同步到路由查询参数。搜索输入防抖提交；点击标签、翻页、清空筛选都会重置页码并重新请求。页面显示当前结果数、可用标签、上一页/下一页和无结果状态。

### 首页、碎碎念与项目

首页并行读取文章、站点配置和最近碎碎念，公告只在后端有值时展示。碎碎念和项目页读取对应公开接口，项目卡片仅在存在有效链接时显示访问入口。

### 文章详情

详情页按以下顺序组织：封面（存在时）、正文、桌面端目录、阅读进度条、复制/收藏操作、上一篇/下一篇、评论区。目录从已渲染正文的二三级标题生成锚点；进度按正文阅读区域计算。移动端目录收起为可展开区域。

## 后端边界与错误处理

公开 handler 仅访问已发布内容，所有分页参数限制为正整数且限制最大值。SQL 继续使用参数绑定；文章标签查询和相邻文章查询放入 repository 层，handler 仅负责参数校验和 JSON 响应。

读取不存在文章时保持现有 404；导航接口在文章不存在时返回 404，在相邻文章不存在时返回 `null`。数据库异常统一返回现有 500 JSON 错误结构。服务启动会创建新表和索引，已存在的数据库可原地升级。

## 验证

测试必须先失败再实现。最低覆盖：

- 后端：文章查询的关键词、标签和分页；标签聚合；相邻文章；notes/projects 的发布过滤与分页；config 不泄露非公开设置。
- 前端：API 响应类型；文章页查询参数与空状态；接口失败不回退示例数据；详情页目录、收藏和导航状态。
- 构建：后端 CMake 构建与测试；两个 Vue 工程的 typecheck 和 production build。

## 验收标准

- `user-web` 业务页面不再导入或显示 `placeholders.ts` 的记录。
- 后端没有数据时，各页面明确展示空状态；不可用时可重试且不展示伪造内容。
- 文章搜索、标签筛选和分页可组合并能通过刷新恢复。
- 首页和公共布局使用后端配置；碎碎念和项目只显示公开数据库数据。
- 文章详情在有数据时提供目录、封面、阅读进度、复制链接、浏览器本地收藏和相邻文章导航。
